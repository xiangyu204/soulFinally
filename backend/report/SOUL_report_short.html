1. 프로젝트 개요

SOUL은 가르칠 수 있는 기술과 배우고 싶은 기술을 등록하면 서로 맞는 사용자를 연결해 주는 기술 교환 플랫폼이다. 앱은 한국어·영어·중국어를 지원하고, 대화에는 AI 번역을 제공한다.

주요 기능설명
회원 · 프로필가입(아이디 중복 확인), 로그인, 프로필 수정, 아바타 업로드
매칭 · 친구추천 매칭, 검색, 친구 신청·수락, 차단, 별명
채팅텍스트·이미지, 회수·삭제, 읽음 표시, AI 번역
통화1:1 음성·영상 통화, 다인 음성방 (Agora)
그 밖의 기능게시판, AI 기술 퀴즈, AI 고객센터
이름담당역할

3. 본인 담당: Android 앱 (메인 UI · 서버 연동)

Kotlin + Jetpack Compose로 만든 앱이며, Kotlin 파일 60개(약 18,700줄), 화면 24개 규모이다. 본인은 메인 UI(화면 구성·디자인)와 서버와의 연결을 맡았다.

3.1 화면 구성

로그인 후 하단 내비게이션 바의 4개 탭(홈 · 탐색 · 매칭 · 채팅)으로 이동하고, 프로필 · 설정 · 고객센터 · AI 퀴즈 · 로그아웃은 왼쪽 프로필 드로어에서 연다.

화면핵심 내용서버 연동
홈사용자가 구슬로 떠 있는 회전 3D 행성(Canvas로 직접 그림), 매칭 시작 버튼findMatches, fetchProfile
탐색검색창, 카테고리 칩 7개, 사용자 카드. 검색은 300ms 지연 후 요청findMatches, searchUsers
매칭탭 4개(추천·친구·받은 신청·차단), 수락/거절/차단/별명, 매칭 성사 다이얼로그acceptMatch, respondFriendRequest 외
채팅말풍선, 텍스트·이미지 전송, 회수·삭제, 번역 토글, 통화 버튼. 전송하면 입력창을 즉시 비움fetchMessages, sendMessage, sendImage 외
로그인 · 가입입력 검사(아이디 3~20자, 이메일 형식, 비밀번호 6자 이상·일치), 로딩·오류 표시login, checkUsername, register
프로필내 정보, 수정(사진 업로드), 상대 프로필(매칭률·별점·레이더 차트)fetchProfile, uploadAvatar 외
AI 퀴즈10문제 풀이, 진행 바, 점수·수준 표시generateQuiz, submitAnswers

3.2 UI 디자인

  • 콘셉트: 우주 테마. 다크 모드는 별이 반짝이는 짙은 배경과 청록·보라, 라이트 모드는 따뜻한 베이지·주황.
  • 유리 질감: soulGlass() 하나로 뒤 배경 블러 + 반투명 그라디언트 + 테두리를 적용하여 카드마다 같은 모습을 유지.
  • 재사용 부품: 카드, 그라디언트 버튼, 태그, 아바타, 스킬 칩 등을 공통 컴포넌트로 만들어 모든 화면에서 사용.
  • 테마·언어 전환: 다크/라이트와 한국어·영어·중국어를 앱에서 바로 바꿀 수 있다.

3.3 서버 연동 방식

화면은 서버를 직접 부르지 않고 화면 → ViewModel → Retrofit → 서버 순서로 연결된다. ViewModel이 결과를 상태(로딩 / 성공 / 오류)로 바꿔 주면 화면은 그 상태만 보고 그린다.

  • API 선언: SoulApiService에 서버 엔드포인트 49개를 함수로 선언 (퀴즈 2개는 별도 인터페이스). 함수만 선언하면 Retrofit이 요청 코드를 만든다.
  • 서버 주소: 빌드 설정으로 지정. 에뮬레이터 기본값은 PC를 가리키는 http://10.0.2.2:8080/이며, 로그인 화면에서 주소를 바꿀 수도 있다.
  • 타임아웃: 일반 API 15초, AI 퀴즈는 읽기 60초 (AI 응답이 느려서).
  • 자동 갱신: 서버가 먼저 알려 주는 방식이 없어 앱이 주기적으로 묻는다 — 채팅 약 2.5초, 채팅 목록·친구 신청 약 3초, 통화 수신 약 1.5~2초, 새 메시지 알림 약 5초.
// AuthViewModel.login() — 요약
viewModelScope.launch {
    _loginResult.value = LoginResult.Loading
    val response = apiService.login(LoginRequest(username, pass))
    if (response.isSuccessful && response.body()?.success == true)
        _loginResult.value = LoginResult.Success(username = body.username ?: username)
    else
        _loginResult.value = LoginResult.Error(body?.message ?: "Login failed")
}

// SoulApiService — Retrofit 선언
@POST("api/login")
suspend fun login(@Body request: LoginRequest): Response<LoginResponse>

※ 위 ViewModel 코드는 원본을 요약한 것이고, 인터페이스 선언은 원본 그대로이다.

3.4 음성·영상 통화 (Agora) [담당 확인]

  • 발신: 서버에 통화 시작을 요청하고 상대가 받을 때까지 상태를 확인한다. 수신: 로그인 후 주기적으로 걸려 온 통화를 확인해 수락/거절 화면(오버레이)을 띄운다.
  • 통화가 성사되면 서버에서 Agora 임시 토큰을 받아 Agora 채널에 직접 입장한다. 앱에는 Agora 인증서를 두지 않는다.
  • 통화 중 음소거, 카메라 켜기/끄기·전환, 상대 소리 끄기를 지원한다.

4. 문제 해결 과정

4.1 에뮬레이터에서 서버 접속

에뮬레이터 안의 localhost는 에뮬레이터 자신이라 PC의 서버에 닿지 않는다. 그래서 기본 주소를 10.0.2.2로 두고, 실제 기기에서는 PC의 IP를 입력하도록 했다. [앱 개발 중 겪은 다른 문제와 해결 추가]

5. 실행 방법 및 시연

  1. MariaDB를 켜고 서버(SoulBackendApplication)를 실행한다 — 포트 8080, 서버는 하나만.
  2. Android Studio에서 app/soul-android를 열어 에뮬레이터로 실행한다. 통화는 마이크·카메라 권한이 필요하다.

※ 초안입니다. 본인의 경험에 맞게 고쳐 쓰세요.

Android 앱의 메인 UI와 서버 연동을 맡아, 화면이 ViewModel과 Retrofit을 거쳐 서버와 데이터를 주고받는 흐름을 구체적으로 이해하게 되었다. 에뮬레이터에서 서버에 접속하지 못하는 문제처럼 환경 차이로 생기는 오류를, 추측하지 않고 하나씩 확인하며 원인을 좁혀 가는 방법을 배웠다. 보안(키 보관, 비밀번호 저장)과 실시간성은 아쉬운 점이어서 이후 우선 개선하고 싶다.
