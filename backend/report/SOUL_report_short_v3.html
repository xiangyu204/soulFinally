1. 프로젝트 개요

SOUL은 가르칠 수 있는 기술과 배우고 싶은 기술을 등록하면 서로 맞는 사용자를 연결해 주는 기술 교환 플랫폼이다. 사용자는 Android 앱으로 이용하고, 앱은 백엔드 서버의 REST API와 통신한다.

주요 기능설명
회원 · 프로필가입(아이디 중복 확인), 로그인, 프로필 수정, 아바타 업로드
매칭 · 친구추천 매칭, 검색, 친구 신청·수락, 차단, 별명
채팅텍스트·이미지, 회수·삭제, 읽음 표시, AI 번역·답장 도움
통화1:1 음성·영상 통화, 다인 음성방 (Agora)
그 밖의 기능게시판, AI 기술 퀴즈

3. 백엔드 개발 내용 (주 담당)

3.1 데이터베이스 설계

JPA 엔티티로 테이블을 정의하고, ddl-auto=update 설정으로 서버 시작 시 Hibernate가 테이블을 자동 생성·갱신한다. 총 12개 테이블이다. [HeidiSQL 테이블 목록 캡처]

테이블용도제약
users회원 정보, 보유/희망 기술, 국적, 평점, 권한username 유일
friends / friend_requests친구 관계 / 신청과 처리 상태(userA, userB) 유일
blocks / remarks차단 / 친구별 별명쌍 단위 유일
user_matches매칭 기록(userA, userB) 유일
messages채팅 메시지(텍스트·이미지·통화 기록), 회수 여부내용 4000자
message_reads / message_deletions마지막 읽은 메시지 / 본인 화면에서만 삭제-
chat_ratings채팅 평가 점수-
board_posts / board_comments게시글과 댓글내용 4000자 / 2000자
  • 테이블 간 연결은 외래키 대신 username 문자열로 한다.
  • 친구·차단·별명·매칭에는 복합 유일 제약을 두어 같은 데이터가 두 번 저장되지 않게 했다.
  • 통화·음성방·AI 퀴즈처럼 오래 보관할 필요가 없는 임시 상태는 DB가 아닌 메모리(Store)에서 관리한다.

3.2 REST API (총 62개)

모든 API는 /api/ 아래에 있고 요청·응답은 JSON이다 (이미지 업로드만 multipart).

모듈개수주요 기능 · 업무 규칙
사용자9로그인, 가입, 아이디 중복 확인(3~20자 영문·숫자·밑줄, 아이디·이름 모두 유일), 프로필, 아바타 업로드
매칭·검색4추천 매칭(이미 매칭된 사용자 제외, 기술 키워드 필터), 사용자 검색
친구·관계10신청(친구이거나 대기 중이면 중복 생성 안 함), 수락해야 친구 관계 생성, 차단, 별명, 관계 상태
채팅12차단·친구 확인 후 전송, 4000자·이미지 10MB 제한, 2분 내 회수, 읽음 처리, AI 답장 도움
게시판7작성자만 삭제, 게시글 삭제 시 댓글도 삭제, 댓글 수 자동 갱신
통화6친구끼리만 통화, 상태 RINGING → ACTIVE → ENDED/REJECTED, 거절·종료 시 통화 기록 메시지 추가, Agora 토큰
음성방8생성·초대·응답·퇴장·방 메시지, 최대 8명, 빈 방 자동 삭제
AI4번역, 매칭 가이드, AI 대화 (실패해도 오류 대신 대체 응답)
퀴즈210문제 생성(객관식 8·주관식 2), 객관식은 서버가, 주관식은 AI가 채점, 정답률 80%/50%로 수준 판정

3.3 외부 API 연동

  • DeepSeek (client/DeepSeekClient): JDK HttpClient로 chat/completions에 POST. 키는 설정 파일에서 @Value로 주입하며 코드에 직접 쓰지 않는다. 연결 30초·요청 120초 타임아웃. 번역·매칭 가이드·AI 대화·퀴즈 생성/채점에 사용하고, 번역 프롬프트는 한국어 존댓말, 일본어 です・ます체 등 정중한 문체를 지시한다.
  • Agora: 서버는 공식 라이브러리로 유효기간 1시간의 RTC 토큰만 만든다. 음성·영상 데이터는 앱이 Agora에 직접 연결하므로 서버를 거치지 않아 부하가 작다.

public LoginResponse login(@RequestBody LoginRequest req) {

3.5 부가 기능

  • 파일 업로드: 아바타·채팅 이미지를 uploads/에 UUID를 붙여 저장하고 /uploads/**로 제공 (한도 20MB).
  • CORS: 모든 출처 허용(개발·시연용).   초기 데이터: 시작 시 DataSeeder가 시연용 데이터를 넣는다.

4. Android 앱 개발 내용 (부 담당)

Kotlin + Jetpack Compose로 만든 앱(Kotlin 파일 60개, 약 18,700줄, 화면 24개)에서 본인은 메인 UI와 서버 연동을 맡았다. [담당 화면 범위 확인]

  • 화면: 하단 탭 4개(홈 · 탐색 · 매칭 · 채팅)와 왼쪽 프로필 드로어(프로필 · 설정 · 고객센터 · AI 퀴즈). 홈은 사용자가 구슬로 떠 있는 회전 3D 행성을 Canvas로 직접 그렸고, 탐색은 검색(300ms 지연 후 요청)과 카테고리 칩, 매칭은 4개 탭과 매칭 성사 다이얼로그, 채팅은 이미지 전송·회수·번역 토글을 제공한다.
  • 디자인: 우주 테마와 유리 질감(Haze 블러)을 soulGlass() 하나로 적용하고, 카드·버튼·아바타 등을 공통 부품으로 재사용한다. 다크/라이트와 한·영·중 전환을 지원한다.
  • 서버 연동: 화면 → ViewModel → Retrofit → 서버 구조. SoulApiService에 위 서버 API를 함수 49개로 선언하고, ViewModel이 결과를 로딩/성공/오류 상태로 바꿔 화면에 전달한다. 서버 주소는 에뮬레이터 기본값 http://10.0.2.2:8080/이며 로그인 화면에서 바꿀 수 있다.
  • 자동 갱신: 서버가 먼저 알려 주는 방식이 없어 앱이 주기적으로 묻는다 — 채팅 약 2.5초, 채팅 목록·친구 신청 약 3초, 통화 수신 약 1.5~2초.
  • 통화 [담당 확인]: 서버에서 받은 Agora 토큰으로 채널에 직접 입장하고, 음소거·카메라 전환 등을 제공한다.

5. 문제 해결 과정

5.1 서버가 DB에 연결되지 않음 (BadAuthenticationPlugin)

증상서버 실행 시 BadAuthenticationPlugin 오류로 종료, 포트 8080이 열리지 않음
원인 분석DB가 MySQL이 아닌 MariaDB 13임을 확인. root 계정의 인증 방식은 이미 정상이라 계정 문제가 아니었고, 연결 옵션을 바꿔도 동일 → MySQL 공식 드라이버가 MariaDB 13의 접속 방식을 처리하지 못하는 것으로 결론.
해결pom.xml의 드라이버를 MariaDB 공식 드라이버로 교체하고 접속 주소를 jdbc:mariadb://로 변경 후 재빌드.
결과서버가 2.5초 만에 기동하고 DB 연결·JPA 초기화 성공.

[오류 로그 캡처] [정상 기동 로그 캡처]

5.2 그 밖의 문제

  • 포트 8080 충돌: 서버를 두 번 실행해 같은 포트를 쓰려다 실패 → 점유한 프로세스를 종료하고 한 개만 실행.
  • 에뮬레이터에서 서버 접속: 에뮬레이터의 localhost는 자기 자신이라 PC 서버에 닿지 않음 → 기본 주소를 10.0.2.2로 설정.

8. 한계 및 개선 계획

분류현재 상태개선 방안
비밀번호평문으로 저장·비교BCrypt 해시 (Spring Security)
사용자 인증요청의 username 값으로 사용자를 식별, 로그인 토큰 없음로그인 시 JWT 발급, 서버에서 토큰으로 확인
비밀 정보API 키·DB 비밀번호가 설정 파일에 있고, 앱 고객센터 화면은 DeepSeek를 앱에서 직접 호출하며 키가 앱 코드에 있음환경 변수로 분리, 앱은 서버의 AI API만 호출
임시 상태통화·음성방·퀴즈가 메모리에 있어 재시작 시 소실DB 또는 Redis로 이전, 동시성 안전 자료구조
데이터 무결성외래키·스키마 이력 없음, CORS 전체 허용외래키, Flyway, 허용 도메인 제한
실시간성앱이 주기적으로 조회(폴링)WebSocket 또는 푸시(FCM)
테스트자동화 테스트 없음MockMvc 기반 API 테스트

9. 느낀 점

※ 초안입니다. 본인의 경험에 맞게 고쳐 쓰세요.

백엔드에서 REST API와 DB, 외부 API 연동을 구현하며 서버가 앱과 데이터베이스, 외부 서비스 사이에서 하는 역할을 구체적으로 이해하게 되었다. DB 연결 오류를 해결할 때는 오류 메시지만 보고 설정을 바꾸는 대신, 실제 DB 종류와 계정 설정을 하나씩 확인해 원인을 좁혀 가는 방법을 배웠다. 앱 쪽 연동을 함께 하면서 API를 만드는 입장과 쓰는 입장을 모두 경험했고, 비밀번호 저장과 인증 토큰 같은 보안 부분은 이후 가장 먼저 개선하고 싶다.
