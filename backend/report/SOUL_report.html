1. 프로젝트 개요

1.1 프로젝트 소개

SOUL은 사용자가 자신이 가르칠 수 있는 기술과 배우고 싶은 기술을 등록하면, 서로 필요한 기술이 맞는 사용자를 연결해 주는 기술 교환 플랫폼이다. 한국어·영어·중국어 등 서로 다른 언어를 쓰는 사용자도 이용할 수 있도록 앱은 3개 언어를 지원하고, 대화에는 AI 번역 기능을 제공한다. 사용자는 Android 앱으로 서비스를 이용하며, 앱은 백엔드 서버의 REST API와 통신한다.

4. 연동 대상: 백엔드(서버) 개요

※ 이 장은 앱이 연동하는 서버의 구조를 설명한다. 서버 개발 담당: [담당 팀원]. 본인은 이 서버의 API 명세를 기준으로 앱을 연동하였고, 서버 실행·DB 연결 환경을 구성하고 연결 오류를 해결하는 일(6장)에 참여하였다.

4.1 데이터베이스 설계

JPA 엔티티로 테이블을 정의하고, spring.jpa.hibernate.ddl-auto=update 설정으로 서버 시작 시 Hibernate가 테이블을 자동 생성·갱신한다. 총 12개 테이블이며, HeidiSQL에서 생성된 것을 확인하였다. [HeidiSQL 테이블 목록 스크린샷 삽입]

테이블엔티티용도제약 조건
usersUser회원 정보, 보유/희망 기술과 수준, 국적, 평점, 권한username 유일
friendsFriend친구 관계(userA, userB) 유일

4.3 외부 API 연동

(1) DeepSeek 대규모 언어 모델

  • 구현 위치: client/DeepSeekClient.java. JDK 기본 HttpClient로 https://api.deepseek.com/chat/completions에 POST 요청을 보낸다 (모델 deepseek-chat, 비스트리밍).
  • 인증: Authorization 헤더에 Bearer 토큰을 사용한다. 키 값은 설정 파일에서 @Value로 주입하며 코드에 직접 쓰지 않는다.
  • 타임아웃: 연결 30초, 요청 120초. HTTP 200이 아니면 예외를 던진다.
  • 사용처: ① 메시지 번역 ② 매칭 가이드 ③ AI 대화 ④ 채팅 답장 도움 ⑤ 기술 테스트 문제 생성 ⑥ 주관식 채점.
  • 번역 프롬프트: 한국어는 존댓말(~습니다/~요), 일본어는 です・ます체, 중국어는 정중한 표현을 쓰도록 지시하고, 번역문만 출력하도록 제한하였다.

(2) Agora 실시간 음성·영상

  • 서버는 Agora 공식 라이브러리(RtcTokenBuilder2)로 유효기간 1시간의 RTC 토큰만 생성한다 (GET /api/call/token).
  • 클라이언트는 이 토큰으로 Agora 서버에 직접 접속하므로, 음성·영상 데이터는 우리 서버를 거치지 않는다. 서버 부하가 작다.
  • 채널 이름은 두 사용자 이름을 정렬해 A|B 형태로 만들어, 누가 먼저 걸어도 같은 채널이 되도록 했다. 음성방은 soul_room_<roomId>를 사용한다.

5. Android 앱 개발 내용 (본인 담당: 메인 UI · 서버 연동)

5.1 개요

Android Studio에서 Kotlin + Jetpack Compose로 SOUL 앱을 개발하였다. 본인은 이 앱의 메인 UI(화면 구성과 디자인)와 백엔드 서버와의 연결(API 연동)을 담당하였다. 앱은 4장에서 설명한 서버의 REST API를 호출하고, 음성·영상 통화는 Agora SDK로 처리한다.

5.5 서버(API) 연동 방식

  • Retrofit 인터페이스: SoulApiService에 서버 엔드포인트 49개를 suspend 함수로 선언했다 (로그인, 회원가입, 프로필, 매칭, 친구, 채팅, 통화, 음성방, AI 등). 퀴즈 2개는 QuizApiService가 맡는다. 호출 대상은 4장에서 설명한 백엔드 API이다.
  • 서버 주소: 빌드 설정의 API_BASE_URL에서 읽는다. 기본값은 에뮬레이터에서 PC의 서버로 접속하는 주소 http://10.0.2.2:8080/이다. 실제 기기용 빌드는 -PapiBaseUrl=http://<PC의 IP>:8080/ 옵션으로 바꾼다.
  • 실행 중 주소 변경: 로그인 화면에서 서버 주소를 입력하면 ServerConfig가 이를 SharedPreferences에 저장하므로, 서버 주소가 바뀌어도(예: 외부 접속용 터널 주소) 앱을 다시 빌드할 필요가 없다.
  • 타임아웃: 일반 API는 연결·읽기·쓰기 15초. AI 기능(퀴즈)은 연결 30초, 읽기 60초로 길게 잡았다 (AI 응답이 느리기 때문).
  • 디버그 로그: 디버그 빌드에서만 요청·응답 본문을 Logcat에 출력하고, 릴리스 빌드에서는 끈다.
  • 오류 처리: ViewModel이 성공 / 로딩 / 오류 상태를 StateFlow로 노출하고, 화면은 이를 보고 메시지를 보여 준다.

5.6 음성·영상 통화 (Agora) 구현

call/CallManager.kt가 1:1 통화 전체를 맡고, RoomManager.kt가 다인 음성방을 맡는다. 통화 화면과 음성방은 CallOverlay, RoomOverlay로 앱 어디서나 표시된다.

단계동작
① 발신startCall()이 서버에 통화 시작을 요청(POST /api/call/start)하고, 상대가 받을 때까지 서버 상태를 주기적으로 확인(pollOutgoingStatus)한다.
② 수신로그인 후 startIncomingPolling()이 약 1.5~2초 간격으로 서버에 걸려 온 통화가 있는지 묻는다(GET /api/call/incoming). 있으면 오버레이로 수락/거절 화면을 띄운다. 알림 서버(푸시) 없이 폴링으로 구현했다.
③ 토큰 받기통화가 성사되면 서버의 GET /api/call/token으로 Agora 임시 토큰을 받는다. 앱에는 Agora 인증서를 두지 않는다.
④ 채널 입장RtcEngine.joinChannel()로 Agora에 직접 접속한다. 영상 통화일 때만 카메라를 켠다.
⑤ 통화 중내 음소거, 카메라 켜기/끄기, 카메라 전환, 상대 소리 끄기를 제공한다. 상대 입장·퇴장은 IRtcEngineEventHandler 콜백으로 감지한다.
⑥ 종료endCall()이 서버에 종료를 알리고(POST /api/call/end) 채널을 나간다. 거절·취소도 같은 방식이다.

이를 위해 AndroidManifest에 INTERNET, RECORD_AUDIO, CAMERA, MODIFY_AUDIO_SETTINGS, BLUETOOTH, POST_NOTIFICATIONS 권한을 선언했다. [통화 화면 캡처: 발신 / 수신 / 영상 통화 중]

5.7 주요 코드

(1) 로그인 — AuthViewModel.login() (가독성을 위해 줄바꿈을 정리하고 일부 생략)

fun login(username: String, pass: String) {
    viewModelScope.launch {
        _loginResult.value = LoginResult.Loading
        try {
            val response = apiService.login(LoginRequest(username, pass))
            if (response.isSuccessful) {
                val body = response.body()
                if (body?.success == true) {
                    _loginResult.value = LoginResult.Success(username = body.username ?: username)
                } else {
                    _loginResult.value = LoginResult.Error(body?.message ?: "Login failed")
                }
            } else {
                _loginResult.value = LoginResult.Error("Server error: ${response.code()}")
            }
        } catch (e: Exception) { /* 네트워크 오류 메시지 처리 */ }
    }
}

화면은 loginResult(StateFlow)를 관찰하다가 Success가 되면 홈으로 이동한다. 이것이 앱 전체에서 쓰는 MVVM 패턴의 기본 형태이다.

(2) 서버 API 선언 — SoulApiService (Retrofit)

@POST("api/login")

@GET("api/chat/messages")

인터페이스에 함수만 선언하면 Retrofit이 HTTP 요청 코드를 만들어 준다. 4장의 POST /api/login, GET /api/chat/messages와 같은 경로이다.

6. 문제 해결 과정 (트러블슈팅)

6.1 서버가 DB에 연결되지 않음 — BadAuthenticationPlugin

증상서버 실행 시 java.sql.SQLException: !AuthenticationProvider.BadAuthenticationPlugin! 가 발생하고 서버가 종료됨. 포트 8080이 열리지 않음.
원인 분석① 3306 포트에서 실행 중인 DB가 MySQL이 아니라 MariaDB 13.0.2임을 HeidiSQL 접속 화면과 Windows 서비스 목록으로 확인. ② mysql.user 조회 결과 root 계정의 인증 플러그인은 이미 mysql_native_password여서 계정 설정은 문제가 아님. ③ JDBC URL에 인증 플러그인 옵션을 지정해 보았으나 동일 오류 → MariaDB 13의 핸드셰이크를 MySQL 공식 드라이버(mysql-connector-j 8.3.0)가 처리하지 못하는 것으로 결론.
해결pom.xml의 드라이버를 org.mariadb.jdbc:mariadb-java-client(Spring Boot 관리 버전 3.3.3)로 교체하고, JDBC URL 접두어를 jdbc:mysql://에서 jdbc:mariadb://로 변경한 뒤 Maven으로 다시 패키징.
결과Started SoulBackendApplication in 2.519 seconds, HikariPool이 org.mariadb.jdbc.Connection으로 연결 성공, JPA 초기화 완료.

[오류 로그 스크린샷]   [해결 후 정상 실행 로그 스크린샷]

6.2 포트 8080 충돌

증상: Web server failed to start. Port 8080 was already in use.   원인: 같은 서버를 두 번 실행하여 두 프로세스가 같은 포트를 사용하려 함.   해결: 포트를 점유한 java 프로세스를 확인해 종료하고 서버를 하나만 실행.

6.3 개발 환경 설정

PATH에 java, mvn이 없어 명령줄 실행이 되지 않았다. IntelliJ의 JDK와 내장 Maven을 직접 지정하여 빌드·실행하였다.

6.4 앱 개발 중 문제 해결

에뮬레이터에서 서버에 접속: 에뮬레이터 안에서 localhost는 에뮬레이터 자신을 가리켜 PC에서 실행 중인 서버에 접속되지 않는다. 그래서 앱의 기본 서버 주소를 PC를 가리키는 특수 주소 http://10.0.2.2:8080/로 설정하고, 실제 기기에서는 PC의 IP나 외부 터널 주소를 로그인 화면에서 입력하도록 했다.

7. 실행 방법 및 시연 계획

7.1 실행 방법

  1. MariaDB 서비스(서비스 이름 MariaDB)가 실행 중이고 soul 스키마가 있는지 확인한다.
  2. IntelliJ에서 SoulBackendApplication을 실행한다 (서버는 한 개만 실행).
  3. 로그에 Tomcat started on port 8080, Started SoulBackendApplication이 나오면 정상이다.

명령줄로 실행할 때는 mvn -DskipTests package 후 java -jar target/soul-backend-0.0.1-SNAPSHOT.jar를 사용한다.

Android 앱 실행

  1. 백엔드 서버를 먼저 실행한다 (포트 8080).
  2. Android Studio에서 app/soul-android 프로젝트를 열고 Gradle 동기화를 한다.
  3. 에뮬레이터에서 실행하면 서버 주소가 http://10.0.2.2:8080/로 연결된다. 실제 기기는 -PapiBaseUrl=http://<PC의 IP>:8080/로 빌드하거나 로그인 화면에서 서버 주소를 입력한다.
  4. 통화 기능은 마이크·카메라 권한을 허용해야 한다.
